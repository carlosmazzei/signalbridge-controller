# Command Protocol Reference

This document describes the firmware command protocol used by the USB CDC
interface, including packet framing, payload layouts, and practical examples.
It reflects the behavior implemented in the current firmware sources.

## Transport and framing

- **Transport:** USB CDC (TinyUSB)
- **Framing:** COBS (Consistent Overhead Byte Stuffing)
- **Packet delimiter:** `0x00` (COBS packet marker)
- **Checksum:** XOR of all header + payload bytes (1 byte)

### Decoded packet layout (before COBS encoding)

```
Byte 0  : ID high bits (upper 8 bits of the 11-bit board ID)
Byte 1  : ID low bits (upper 3 bits) + command (lower 5 bits)
Byte 2  : Payload length (N)
Byte 3..(3+N-1) : Payload bytes
Byte 3+N        : XOR checksum (bytes 0..(2+N))
```

**Board ID packing (11-bit ID):**

```
rxID = (byte0 << 3) | ((byte1 & 0xE0) >> 5)
cmd  = byte1 & 0x1F
```

The firmware expects `rxID` to match `BOARD_ID` (configured as `0x01`).

**COBS framing:** The decoded bytes above are COBS-encoded and terminated with
`0x00` on the wire.

## Inbound validation and error counters

Valid packets contain at most 24 decoded bytes (3-byte header, up to 20 payload
bytes, and 1 checksum byte), which encode to at most 25 COBS bytes plus the
`0x00` delimiter: 26 bytes on the wire.

Inbound processing applies these checks in order:

1. The encoded framer reports `RECEIVE_BUFFER_OVERFLOW_ERROR` when the 26th
   non-delimiter byte arrives without a `0x00`. It discards all following bytes
   through the next `0x00`; that delimiter only re-arms the framer and does not
   increment another counter.
2. An empty frame (`0x00` with nothing buffered), or a COBS decode failure
   (including a truncated block, embedded zero, or zero code byte), increments
   `COBS_DECODE_ERROR`.
3. A decoded length below 4 bytes, or a decoded length that differs from the
   header's payload length (`len`) plus 4, increments `MSG_MALFORMED_ERROR`.
4. A payload length `len` greater than 20 increments `BUFFER_OVERFLOW_ERROR`.
   This check is defensive: a frame with `len` greater than 20 is at least 25
   decoded bytes and therefore at least 26 COBS bytes, so the framer rejects it
   first on the wire as `RECEIVE_BUFFER_OVERFLOW_ERROR`.
5. A board ID different from `BOARD_ID` increments `UNKNOWN_CMD_ERROR`.
6. An XOR checksum mismatch increments `CHECKSUM_ERROR`.
7. `PC_PWM_CMD`, `PC_ERROR_STATUS_CMD`, and `PC_TASK_STATUS_CMD` require a
   payload length of exactly 1; otherwise they increment `MSG_MALFORMED_ERROR`.
   An otherwise valid but unrecognized command also increments
   `UNKNOWN_CMD_ERROR`.

Frames queued during a previous USB session are dropped without incrementing a
counter.

## Payload formats (implemented)

### PWM update (`PC_PWM_CMD`, 0x01)

- **Direction:** Host → Device
- **Length:** 1 byte
- **Payload:**
  - `payload[0]`: duty cycle (`0x00`–`0xFF`)

### LED update (`PC_LEDOUT_CMD`, 0x02)

- **Direction:** Host → Device
- **Length:** 3 bytes
- **Payload:**
  - `payload[0]`: controller ID (1–8)
  - `payload[1]`: column index of the 8x8 LED matrix (0–7, 0-based; column 0 = first column)
  - `payload[2]`: column LED bitmask; bits 0–3 drive SEG1–SEG4 of the column (written to the low nibble of address `payload[1] * 2`), bits 4–7 drive SEG9–SEG12 (written to the low nibble of address `payload[1] * 2 + 1`). `1` = LED on, `0` = LED off. Unused high nibbles are always kept at zero.

### Display control (`PC_DPYCTL_CMD`, 0x0A)

> Note: The **packet header** contains the board ID and command.
> The **first payload byte encodes the controller ID and display command**.

- **Direction:** Host → Device
- **Length:** 6 bytes for digit updates, 2 bytes for brightness updates
- **Payload header byte layout (`payload[0]`):**
  - Upper 3 bits: controller ID (1-based)
  - Lower 5 bits: display command
  - `controller_id = (payload[0] >> 5) & 0x07`
  - `display_cmd = payload[0] & 0x1F`
- **Display command values:**
  - `0x00`: set digits
  - `0x01`: set brightness
- **Payload (digit update):**
  - `payload[0]`: controller/command byte (`0x20` for controller ID 1, set digits)
  - `payload[1]..payload[4]`: packed BCD digits (two digits per byte)
  - `payload[5]`: dot position/flags passed to the driver
- TM1639 consumes all eight packed digits; TM1637 consumes the first four (bytes 1–2). The six-byte wire payload is unchanged; remaining digits are ignored by TM1637. Display IDs are 1–7; ID 0 is invalid, and the current three-bit encoding cannot address slot 8.
- **Payload (brightness update):**
  - `payload[0]`: controller/command byte (`0x21` for controller ID 1, set brightness)
  - `payload[1]`: brightness: 0 turns the display off, 1–8 select increasing brightness; values above 8 clamp to 8

### Echo (`PC_ECHO_CMD`, 0x14)

- **Direction:** Host → Device (request), Device → Host (response)
- **Length:** any
- **Behavior:** Device returns the same payload.

### Error status (`PC_ERROR_STATUS_CMD`, 0x17)

- **Request length:** 1 byte
- **Request payload:**
  - `payload[0]`: error counter index

- **Response length:** 5 bytes
- **Response payload:**
  - `payload[0]`: index
  - `payload[1..4]`: 32-bit counter value (big-endian)

### Task status (`PC_TASK_STATUS_CMD`, 0x18)

- **Request length:** 1 byte
- **Request payload:**
  - `payload[0]`: task index
    - `0`–`7`: application task
    - `8` (`NUM_TASKS`): idle-task runtime and minimum-free-heap statistics
    - `9` (`WATCHDOG_TASK_STATUS_INDEX`): watchdog supervisor runtime and stack watermark
    - Greater than `9`: response is a single byte `0xFF`.

- **Response length:** 13 bytes for indices `0`–`9`; invalid indices receive a one-byte `0xFF` payload.
- **Response payload:**
  - `payload[0]`: index
  - `payload[1..4]`: runtime counter (big-endian)
  - `payload[5..8]`: runtime percent (big-endian)
  - `payload[9..12]`: stack high watermark (or minimum free heap for index `8`)

### Keypad event (`PC_KEY_CMD`, 0x04)

- **Direction:** Device → Host
- **Length:** 1 byte
- **Payload:**
  - `payload[0] = (column << 4) | (row << 1) | state`
  - `state`: `1` pressed, `0` released

### ADC event (`PC_AD_CMD`, 0x03)

- **Direction:** Device → Host
- **Length:** 3 bytes
- **Payload:**
  - `payload[0]`: channel
  - `payload[1]`: value high byte
  - `payload[2]`: value low byte

### Rotary event (`PC_ROTARY_CMD`, 0x06)

- **Direction:** Device → Host
- **Length:** 2 bytes
- **Payload:**
  - `payload[0]`: `(rotary_index << 4)`
  - `payload[1]`: direction (`1` clockwise, `0` counter-clockwise)

> with the controller ID stored in the upper 3 bits and the display command in
> the lower 5 bits.

## Session and recovery semantics

Only one CDC function is exposed. Both DTR and RTS must be asserted. Reconnecting republishes known key and ADC states, including stable inputs. Encoders are relative best-effort events and are not replayed from disconnected sessions. Delivery tracking ends at TinyUSB FIFO acceptance; the protocol has no application-level acknowledgement. COBS frames with truncated blocks or embedded zero bytes are rejected. After an overlong frame, reception discards bytes through the next delimiter. PWM and indexed status commands require exactly one payload byte.
